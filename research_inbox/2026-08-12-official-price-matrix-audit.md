# AB22BL·AB23BL 공식 공급가 매트릭스 감사

- 감사일: 2026-08-12
- 범위: 모집공고 7~8쪽 `공급금액 표`
- 목적: 사용자가 `블록 + 동 + 층 + 타입`만 선택했을 때 공식 공급가를 `단일값 / 범위 / 불가`로 판정할 수 있는지 검증
- 원문:
  - [`2026000194_AB22BL_입주자모집공고.pdf`](../sources/official/2026000194_AB22BL_입주자모집공고.pdf)
  - [`2026000195_AB23BL_입주자모집공고.pdf`](../sources/official/2026000195_AB23BL_입주자모집공고.pdf)

## 1. 결론

구현은 가능하다. 다만 `공식 공급가`와 `입주까지 필요한 총비용`을 구분해야 한다.

| 판정 | 결과 |
|---|---|
| AB22 | 유효한 `동 + 층 + 타입`이면 전부 단일 공급가 |
| AB23 일반 | 유효한 `동 + 층 + 타입`이면 단일 공급가 |
| AB23 예외 | `6304동 + 84A + 1층/2층`은 1호·3호 라인에 따라 가격이 달라 범위 |
| AB23 84B 특가 | `6304동 + 84B + 2층`은 특별 가격 행이지만 해당 동의 84B가 2호 한 라인뿐이므로 단일값 585,500,000원 |
| 불가 | 해당 동에 타입이 없거나, 공고에 그 타입의 층 가격 행이 없거나, 1층 미만·30층 이상 |
| 확인 필요 | 21~29층은 같은 가격이나 개별 동·라인의 실제 최고층 존재 여부는 7~8쪽만으로 확정 불가 |

핵심 수치:

- 공식 가격 행: 81개 - AB22 39개, AB23 42개
- 동·라인·타입 배정: 115개 - AB22 57개, AB23 58개
- 유효 동·타입 쌍: 67개 - AB22 34개, AB23 33개
- 무효 동·타입 쌍: 63개 - AB22 31개, AB23 32개
- 특별 가격 행: 3개 - AB23 6304동 84A 1층·2층, 84B 2층
- 라인 때문에 범위가 되는 `동+층+타입` 키: 최대 2개 - AB23 6304동 84A 1층·2층

> 주의: 공고의 공급금액은 소유권 이전등기비용, 취득세 등 제세공과금과 추가 선택품목 금액을 포함하지 않는다. 화면 표기는 `공식 공급가`가 맞고 `총비용`이라고 부르면 안 된다.

## 2. 판정 규칙

1. 블록에 속한 동인지 확인한다.
2. 선택 동에 선택 타입의 라인이 존재하는지 확인한다.
3. 선택 층을 공고의 층구간에 매핑한다.
4. 특별 가격 규칙이 있는 동·라인·층이면 특별 가격을 적용한다.
5. 가능한 라인들의 후보 가격이 하나면 `단일값`, 둘 이상이면 `범위`다.
6. 타입 또는 층구간 자체가 없으면 `불가`다.
7. 21~29층 가격은 계산할 수 있지만 실제 해당 동·라인에 선택 층 세대가 있는지는 별도 동호수 원장이 필요하다.

### AB23 6304동 특별 가격

| 동 | 타입 | 라인 | 층 | 특별 공급가 | 같은 타입 기본가 | `동+층+타입` 판정 |

범위 결과:

- `AB23 + 6304 + 1층 + 84A` → 581,000,000~612,400,000원
- `AB23 + 6304 + 2층 + 84A` → 591,600,000~621,000,000원

보수적 주석:

- 2층 84A 기본 행은 특별 행을 제외한 17세대로, 6304동 3호 후보가 존재하는 것으로 판정할 수 있다.
- 1층 84A 기본 행은 12세대이며 공고 7~8쪽에 세부 동호수 원장이 없다. UI에서는 안전하게 범위로 표시하고 `정확한 호 라인을 선택하면 확정` 안내를 붙이는 편이 낫다.
- 6304동 84B는 2호 라인 하나뿐이므로 특별 가격을 기본가와 섞어 범위로 만들면 오류다.

## 5. 입력 불가능·판정 보류 조합

### 즉시 불가

- 블록에 없는 동
- 위 동별 허용 타입에 없는 조합
- 1층 미만 또는 30층 이상
- AB22 84C 1층: 1층 가격 행과 공급세대가 없음
- AB23 59B 1층: 1층 가격 행과 공급세대가 없음

전체 13동×5타입 65쌍 기준 무효 동·타입 쌍:

- AB22: 31쌍
- AB23: 32쌍

### 가격은 계산되지만 실제 세대 존재 확인 필요

- `21층 이상` 행은 21~29층을 한 가격으로 묶는다.
- 단지 최고층은 29층이지만 모든 동·라인이 29층까지 있다는 뜻은 아니다.
- 1층·2층도 필로티·공용시설 때문에 일부 라인에 세대가 없을 수 있다.
- 따라서 `동+층+타입`만으로 가격 규칙은 계산할 수 있어도 실제 계약 가능한 세대 존재성까지 보장하려면 `동·호수 재고 원장`이 필요하다.

권장 UX:

- `불가`: 공고상 타입·층 가격 행 자체가 없는 경우
- `단일값`: 가능한 가격 후보가 하나인 경우
- `범위`: 가능한 라인 후보 가격이 둘 이상인 경우
- `세대 존재 확인 필요`: 가격은 나오나 해당 동의 정확한 층·라인 존재 여부를 7~8쪽만으로 검증하지 못한 경우

## 6. 구조화 TypeScript 타입 제안

```ts
type BlockId = 'AB22' | 'AB23';
type UnitType = '59A' | '59B' | '84A' | '84B' | '84C';
type FloorBand = '1' | '2' | '3-4' | '5-6' | '7-9' | '10-15' | '16-20' | '21-29';

type PriceInput = {
  block: BlockId;
  building: number;
  floor: number;
  unitType: UnitType;
};

type LineAssignment = {
  block: BlockId;
  building: number;
  unitType: UnitType;
  lines: readonly number[];
};

type BasePriceRow = {
  block: BlockId;
  unitType: UnitType;
  floorBand: FloorBand;
  amountWon: number;
  sourcePage: 7 | 8;
};

type PriceOverride = {
  block: BlockId;
  building: number;
  unitType: UnitType;
  line: number;
  floor: number;
  amountWon: number;
  sourcePage: 8;
};

type PriceResolution =
  | {
      kind: 'exact';
      amountWon: number;
      floorBand: FloorBand;
      occupancy: 'confirmed' | 'needs-line-ledger';
    }
  | {
      kind: 'range';
      minWon: number;
      maxWon: number;
      candidates: readonly { line: number; amountWon: number }[];
      reason: 'line-dependent';
    }
  | {
      kind: 'unavailable';
      reason:
        | 'invalid-building'
        | 'type-not-in-building'
        | 'floor-out-of-range'
        | 'no-price-row';
    };
```

데이터 모델 원칙:

- 기본 가격 78행과 특별 가격 3행을 분리한다.
- 특별 행을 기본 가격 배열에 덮어쓰지 않는다.
- `building -> unitType -> lines`를 별도 정규화한다.
- 숫자는 원 단위 정수로 저장하고 화면에서만 포맷한다.
- `21층 이상`을 무한 범위로 두지 말고 공고의 단지 최고층 29층으로 제한한다.
- 옵션, 취득세, 등기비, 금융비용은 공급가 데이터에 섞지 않는다.

## 8. 검증 기록

### 수행한 검증

- 두 PDF의 7~8쪽을 각각 2.5배 PNG로 렌더링해 표의 병합 셀·라인 목록·층구간·공급금액을 시각 확인했다.
- 같은 페이지에서 텍스트를 별도 추출해 숫자 문자열을 교차검증했다.
- 수기 구조화한 공식 가격 81행의 공급금액이 추출 텍스트에 모두 존재하는지 검사했다.
- 결과: 누락 0개.
- 특별 가격 3행을 기본 가격과 분리해 확인했다.
- 6쪽 공급대상 표의 타입별 총공급세대수와 7~8쪽 가격표의 타입 구조를 대조했다.

| `동+층+타입` 가격 판정 | 높음 | 예외 2키를 범위로 처리하면 됨 |
| 정확한 세대 존재성 | 중간 | 개별 동·라인의 실제 시작층·최고층 원장이 없음 |
| 총 입주비용 | 낮음 | 옵션, 세금, 등기, 금융비용은 별도 데이터 필요 |

### 남은 위험

1. 21~29층 구간에서 선택한 정확한 층이 해당 동·라인에 실제 존재하는지 가격표만으로 알 수 없다.
2. 일부 저층은 필로티·공용시설로 세대가 없을 수 있다.
3. AB23 6304동 84A 1층의 일반가 후보는 세부 동호수 원장으로 최종 확인하는 것이 안전하다.
4. 모집공고 정정공고가 나오면 가격 매트릭스를 버전 관리해야 한다.
5. 공급가를 총비용으로 오인시키지 않도록 제외 항목을 결과 카드에 고정 노출해야 한다.
