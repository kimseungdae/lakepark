# 검단레이크파크 실용 기능 후보 — 입주 생존 키트

## 0. 결론

추가 조사에서 가장 큰 변화는 `동·층·타입 3개 선택` 기능의 성격이다. 임의의 층 프리미엄으로 금액을 추정할 필요가 없다. 두 공고의 공식 가격 81행과 동·라인·타입 배정 115개를 이중 대조한 결과, AB22의 유효 가격 규칙은 모두 단일값이고 AB23도 최대 2개 키(`6304동·84A·1층/2층`)만 라인에 따른 범위다. 단, 일부 저층과 21~29층은 선택한 층의 실제 세대 존재 여부를 가격표만으로 확정할 수 없어 `계약서 확인 필요` 상태를 따로 둬야 한다.

따라서 고위험 데이터 검수를 마친 뒤 구현할 핵심은 단순 계산기가 아니라 다음 세 기능을 한 흐름으로 묶은 **`내 납부 안전팩`**이다.

1. `동 → 실제 층 → 타입`으로 공식 공급가격 조회
2. 계약금·중도금 6회·잔금·옵션을 개인 달력과 인쇄용 영수증으로 변환
3. 송금 직전 블록·납부항목·은행·예금주·계약서 계좌를 대조하는 계좌 잠금 카드

그 다음은 입주 통보일부터 작동하는 **`D-Day 입주 생존팩`**이다. 사전방문, 하자 기록, 가구·가전 실측, 이사 견적 비교, 전입신고, 학교·의료·폐기물 확인을 D-60부터 D+14까지 배치한다.

주변 사업과 생활효용 변화는 계속 추적하되 첫 화면의 주인공으로 두지 않는다. 뉴스는 읽고 끝나지만 납부일·계좌·하자·전입·통학 확인은 실제 손실과 재방문을 만든다. 사이트의 기존 운영 원칙에 따라 시세 전망·투자 판단·가격 상승 여부는 제품 후보에서 제외한다.

## 3. `내 납부 안전팩` 상세 기획

### 3.1 사용자 흐름

1. 동 선택: 블록은 동에서 자동 판별한다.
2. 실제 층 선택: `저·중·고층`이 아니라 숫자 층을 받는다.
3. 타입 선택: 해당 동에서 가능한 타입만 노출한다.
4. 공식 공고행 조회: 가격과 납부금액을 한 번에 표시한다.
5. 예외만 라인 확인: 라인 차이로 가격이 갈릴 때만 한 질문을 추가한다.
6. 결과 내보내기: 달력 파일, 인쇄용 영수증, 체크리스트를 사용자가 직접 저장한다.

### 3.2 결과 화면

- `공식 공고 공급가격`: 출처 페이지와 기준일을 함께 표시
- `앞으로 낼 돈`: 2차 계약금, 중도금 1~6회, 잔금
- `별도 계약`: 발코니·추가선택품목은 공급가격과 분리
- `내 달력에 추가`: 각 납부일 ICS 생성
- `송금 전 확인`: 계좌 잠금 카드로 이동
- `누락된 비용`: 세금·등기·대출이자·입주준비비는 개인 조건에 따른 별도 예상임을 표시

각 ICS 설명과 영수증 상단에는 `별도 알림이 없어도 납부의무가 사라지지 않음`, `공급계약서·변경안내 우선`을 넣는다. 입주일이 앞당겨지거나 사용자가 조기입주를 선택하면 미도래 중도금·잔금의 동시 납부 가능성을 경고하고 기존 일정을 폐기한 뒤 ICS를 전부 다시 발급한다.

공급가격과 세금·이자·입주비를 한 숫자로 섞지 않는다. 첫 화면은 공고의 공식 금액, 두 번째 영역은 기본 가정에 따른 계획용 예상 범위로 둔다.

### 3.3 계산이 아니라 조회가 우선인 이유

- 공고에 공식 가격표가 존재한다.
- `저층 20%, 중층 55%, 고층 85%` 같은 임의 위치값이 필요 없다.
- 정확한 층은 사용자가 알고 있고 숫자 선택도 어렵지 않다.
- 동·층·타입만으로 하나의 값이 정해지지 않는 조합은 숨기지 않고 라인 또는 후보 범위를 보여줄 수 있다.
- 잘못된 정밀감보다 원문 페이지를 다시 열 수 있는 공식 조회가 신뢰에 맞다.

## 4. 납부계좌 잠금 카드

AB22와 AB23은 1차 계약금 계좌가 서로 다르고, 같은 블록 안에서도 분양대금·발코니·추가선택품목의 계좌 또는 예금주가 다르다. 2차 계약금·중도금·잔금은 세대별 가상계좌를 사용한다. 지정된 계좌가 아닌 곳에 납부한 금액은 공고상 HUG 분양보증의 보호 대상에서 제외될 수 있다.

사이트는 계좌번호를 편하게 복사해 주는 도구가 아니라 **오송금을 막는 대조 도구**여야 한다.

### 송금 전 완료 조건 5개

1. 내 블록을 확인했다.
2. 납부항목을 확인했다.
3. 예금주를 확인했다.
4. 공고 원문 페이지를 확인했다.
5. 은행·계좌번호를 내 공급계약서와 다시 대조했다.

송금 뒤에는 여섯 번째 단계로 이체확인증 보관 여부를 별도로 확인한다. 성공지표도 `송금 전 5요소 완료율`과 `송금 후 영수증 보관률`로 나눈다.

계좌번호만 단독 노출하거나 블록 확인 전에 복사 버튼을 제공하지 않는다. 중도금 가상계좌는 사이트가 저장하지 않고 계약서 확인 행동만 안내한다.

## 5. D-Day 입주 생존팩

공고의 입주 통보·사전방문 사건을 기준으로 생활 준비를 연결한다. 정확한 날짜가 통지되기 전에는 `예상`, 통지된 뒤에는 `확정` 상태를 사용한다. D-숫자를 고정 달력으로 간주하지 않고 실제 공지일을 입력받아 이후 행동을 다시 계산한다.

| 시점 | 우선 행동 | 사이트가 제공할 것 |
|---|---|---|
| 입주예정월 통보 시점, 약 D-60 | 예정월·잔금자금 확인 | 통지 원문 보관, 납부·대출 준비 갱신 |
| 사전방문 공지·실시 기간 | 하자·실측·동선 점검 | 방별 체크팩, 하자 번호, 가구·가전 실측, 역 보행 감사 |
| 실제 입주가능일 통보 시점, 약 D-30 | 입주지정기간·이사·청소·학교·의료·행정 확인 | 동일조건 견적표, 당일 운영 재확인 링크, 가족 역할 분담 |
| 입주일 | 잔금·열쇠·계량기·공용부 상태 확인 | 입주일 영수증, 계량기 기준선, 사진/서류 백업 |
| D+14 | 전입신고·주소변경·학교 후속 확인 | 정부24·교육청 공식 경로, 처리상태 체크 |
| 지정기간 종료 전 | 미입주 비용·관리비 부과 확인 | 관리주체에 보낼 공식 문의문과 답변 보관 |

### 생활정보의 핵심 원칙

- 2026년 시간표·버스·I-MOD·학구·진료기관·공원 운영정보를 2029년 사실로 복사하지 않는다.
- 역 자전거보관소·환승주차장처럼 현재 공식 목록에서 확인되지 않는 시설은 `없음 확정`이 아니라 `현재 목록에서 미확인`으로 표시한다.
- 학교 신설·학교군·돌봄시설은 개별 세대의 배정·이용 권리를 뜻하지 않는다.
- 병원·약국은 위치보다 방문 당일 운영과 수용 여부를 전화로 확인하게 한다.
- 공원은 준공, 관리기관 인수, 실제 개방, 우천·야간 통제를 서로 다른 상태로 관리한다.

## 6. 뉴스·생활효용 변화를 더 유용하게 바꾸는 법

주변 뉴스를 대량 나열하는 대신 사용자의 다음 행동에 연결한다.

| 일반적인 뉴스 | 사이트에서 바꿀 형태 | 행동 |
|---|---|---|
| 철도 연장 추진 | 행정단계·마지막 확인일·다음 관문 | 새 단계가 확인될 때만 알림 |
| 새 버스 발표 | 계획·실제 노선등록·운행을 분리 | 입주 D-30 버스정보시스템 재조회 |
| 학교 신설 | 계획·공사·개교·학구·배정 분리 | 해당 학년도 고시 저장 |
| 호수공원 조성 | 공사·준공·인수·개방·시설운영 분리 | D-45 낮·밤·우천 후 현장점검 |
| 상권 입점 | 기사 대신 사업자 공식 영업상태 | 실제 개점 후 생활 동선에 추가 |
| 생활권 가치 기대 | 접근성·생활편의·공사불편의 상반 신호 | 예측 대신 실제 이용 가능 상태 제공 |

`상승 호재 점수`는 만들지 않는다. 교통 시간 단축, 생활편의 개장, 학교·돌봄 운영, 공원 접근성처럼 효용이 실제로 열린 사건과 사업 지연·공사 불편 같은 상쇄 신호를 같은 화면에 둔다. 이는 시세 전망이 아니라 입주 생활 의사결정용 상태판이다.

## 7. 데이터·개인정보 경계

- 동·층·타입은 기본적으로 세션에서만 사용하고 자동 저장하지 않는다.
- 호수는 묻지 않는다. 라인 예외도 사용자가 그 자리에서만 선택하게 한다.
- 저장이 필요하면 명시적 `이 기기에 기억` 동의와 전체 삭제 기능을 먼저 제공한다.
- 서버·분석 이벤트에 선택값, 계약금액, 계좌, 사진, 통근 위치를 보내지 않는다.
- 사진은 로컬 저장만 제공하고 EXIF·얼굴·주소 노출을 경고한다.
- 법률·세무·대출 결과에는 기준일, 원문, 재확인 기관을 결과 가까이에 둔다.

현재 사이트는 문자 그대로 `동·호수를 묻지 않는다`고 약속한다. 3탭 조회를 출시하려면 공개 문구를 `호수는 묻지 않음 / 동·층·타입은 조회 중 세션 처리 / 저장은 별도 동의`로 먼저 개정해야 한다. 기존 문구를 유지한다면 이 기능을 출시하지 않는다. 선택 저장을 추가할 경우 기존 `profile.v1`과 분리한 v2 마이그레이션·삭제 사양도 필요하다.

## 8. 추천 구현 순서

정확성 게이트가 다른 두 트랙을 병행한다.

- **즉시 검증 트랙**: 통근 스톱워치, 견적 동일조건 비교표, 사전점검 인쇄 체크팩. 계산·송금을 다루지 않아 빠르게 사용성을 검증할 수 있다.
- **고위험 검수 트랙**: 공식 가격 조회, 납부일, 계좌 잠금. 원문 전수대조와 자동 테스트가 통과하기 전에는 공개하지 않는다.

### 0단계 — 데이터 준비

1. 두 공고의 가격 행을 구조화한다.
2. 동 → 가능한 타입 → 실제 층 → 라인 예외 검증기를 만든다.
3. 공식표의 모든 행과 코드 결과를 대조하는 테스트를 만든다.
4. 블록·납부항목별 계좌 메타데이터를 원문 페이지와 함께 잠근다.
5. 일부 저층과 21~29층의 세대 존재 여부는 별도 동호수 원장이나 계약서 확인 상태로 분리한다.

### 1단계 — 납부 제품

`내 납부 안전팩` 한 화면을 만든다.

- 공식 가격 조회
- 납부 일정 영수증
- ICS·인쇄
- 계좌 대조

성공지표는 페이지뷰가 아니라 `조회 완료율`, `ICS 생성률`, `인쇄율`, `송금 전 5요소 완료율`, `송금 후 영수증 보관률`이다.

### 2단계 — 입주 현장 제품

`입주 행동 캘린더 + 사전점검 체크팩 + 로컬 하자대장`을 연결한다. 공통 로컬 체크 상태, 인쇄 스타일, PDF/JSON 내보내기를 재사용한다.

### 3단계 — 생활 반복 제품

입주 후 실제 관리규약·K-apt·쓰레기·시설 운영 데이터가 생기면 관리비 변화 영수증과 생활 포켓카드를 연다.

### 후속 안전 모듈

- 전매제한·거주의무·재당첨 제한·입주유예를 서로 다른 기준일로 관리하는 권리 시계
- HUG 보증사고 통지를 받았을 때 추가 납부와 예약이체를 점검하고 증빙을 모으는 비상카드
- 조기입주·입주일 변경 시 모든 납부일과 ICS를 재발급하는 변경계약 모드

## 9. 지금 보류할 것

1. **내 납부 안전팩**: 전수대조를 마친 뒤 가장 큰 실용 가치를 검증한다.
2. **D-Day 입주 생존팩**: 입주 전후의 장기 재방문과 현장 사용을 만든다.
