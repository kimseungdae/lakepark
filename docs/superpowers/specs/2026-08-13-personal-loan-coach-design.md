# 맞춤형 대출 코치 설계

- 작성일: 2026-08-13
- 상태: 사용자 방향 승인, 문서 검토 대기
- 대상: `/calculator` 결과의 중도금·입주대출 안내

## 1. 문제 정의

현재 납부 일정은 `cashAmount`만 `내 돈`으로 출력한다. 중도금 60%를 대출로 실행하는 경우 실제 데이터는 `대출 4,866만원 + 내 돈 0원`인데 화면에는 `0원`만 보여 대출이 실행되지 않는 것처럼 보인다.

또한 중도금 대출 총액과 예상 이자를 한 문장으로만 표시해 다음 질문에 답하지 못한다.

- 각 회차에 얼마를 빌리고 이자가 얼마나 쌓이는가?
- 현금이 있다면 어느 회차를 직접 내는 것이 이자를 가장 많이 줄이는가?
- 입주 시 중도금 대출을 어떤 주택담보대출로 전환할 수 있는가?
- 내 소득·가족·자산 조건에서 검토할 정책대출은 무엇인가?
- 예상 대출로도 부족한 입주 자금은 얼마이며 지금부터 어떻게 준비해야 하는가?

## 2. 검토한 접근

### A. 납부표 열만 추가

`납부총액 / 대출 / 내 돈` 세 열을 추가한다. 0원 오해는 즉시 고치지만, 사용자가 무엇을 준비해야 하는지는 여전히 알 수 없다.

### B. 별도 대출 정보 페이지

정책대출 상품을 기사처럼 정리한다. 설명은 풍부하지만 사용자가 계산기에서 본 자기 금액과 연결되지 않아 일반적인 상품 목록에 머문다.

### C. 계산 결과 안의 맞춤형 대출 코치

납부 구조를 정확히 보여준 다음, 개인 조건을 받아 중도금 이자 전략과 입주대출 후보를 같은 금액 흐름 안에서 계산한다. 사용자가 요청한 `내 경우에 무엇을 해야 하나`에 직접 답하므로 이 방식을 채택한다.

## 3. 제품 원칙

1. 상품을 나열하지 않고 선택한 세대의 실제 금액에 연결한다.
2. `가능`, `불가능`을 단정하지 않고 `현재 기준 유력`, `추가 확인`, `현재 조건 미충족`으로 표시한다.
3. 2026년 제도와 금리는 참고 기준이다. 2029년 입주대출 신청 전에 반드시 다시 판정한다.
4. 중도금 직접 납부는 무조건 권하지 않는다. 이자 절감액, 남는 현금, 비상자금, 다른 고금리 부채를 함께 보여준다.
5. 개인 조건은 브라우저에서만 계산한다. 서버 전송은 없고 저장은 별도 동의를 받아야 한다.
6. 공고 확정 금액, 은행 약정에 따른 금액, 정책 기준에 따른 예상 금액을 시각적으로 분리한다.

## 4. 사용자 흐름

### 4.1 즉시 보이는 대출 현황

타입 선택 후 결과 상단에서 다음 네 숫자를 먼저 보여준다.

- `중도금 총액`: 공급금액의 60%
- `예상 대출 실행액`: 선택한 대출 비율에 따라 계산
- `중도금 자납액`: 대출로 충당하지 못하는 금액
- `입주 때 넘겨받을 대출`: 상환하거나 담보대출로 전환할 잔액

납부 일정은 모바일에서 회차 카드, 넓은 화면에서 표로 표시한다. 모든 회차에 `납부총액`, `대출`, `내 돈`을 동시에 표기한다. `내 돈 0원`이면 `전액 대출 예정`을 함께 써서 의미를 설명한다.

### 4.2 중도금 이자 줄이기

기본 시나리오는 회차별로 다음을 계산한다.

- 대출 원금
- 실행일부터 입주예정일까지의 일수
- 선택 금리 기준 예상 이자
- 해당 회차를 직접 납부했을 때 줄어드는 예상 이자

빠른 비교 버튼은 세 개만 둔다.

- `대출 유지`
- `1차만 직접 납부`
- `1·2차 직접 납부`

사용자가 `직접 납부에 쓸 수 있는 현금`과 `남겨둘 비상자금`을 입력하면 다음 문장으로 결과를 요약한다.

> 1·2차를 직접 내면 입주 때까지 예상 이자 약 1,189만원을 줄일 수 있습니다. 납부 후 가용 현금은 약 3,200만원입니다.

이 문장은 선택 금리와 입주예정일을 사용한 계획용 추정이다. 1·2차가 유리한 이유는 금액이 같을 때 대출 기간이 가장 길어 누적 이자가 크기 때문이다.

다음 조건 중 하나면 `추천` 대신 `먼저 확인`을 표시한다.

- 직접 납부 후 비상자금이 사용자 목표보다 적음
- 중도금 금리보다 높은 다른 부채가 있음
- 집단대출 약정에서 회차별 자납·부분상환 가능 여부를 확인하지 않음
- 중도상환수수료가 있는 실행 완료 대출을 상환하려는 경우

현금의 기회비용도 숨기지 않는다. `대출금리와 비교할 손익분기 수익률`을 보여주고, 세후 안전수익률이 이보다 높거나 유동성이 더 중요하면 대출 유지가 나을 수 있다고 안내한다.

### 4.3 내게 맞는 입주대출 찾기

결과 아래 `내 조건으로 다시 보기`에서 한 번만 다음 값을 받는다.

- 생년월일
- 혼인 상태: 미혼 / 결혼예정 / 기혼
- 세대원 전원 무주택 여부
- 생애최초 주택구입 여부
- 부부합산 연소득
- 부부합산 순자산
- 미성년 자녀 수와 최근 2년 내 출생·입양 자녀 여부
- 청년주택드림청약통장으로 해당 주택에 당첨됐는지
- 통장 가입기간 1년·납입실적 1,000만원 충족 여부
- 기존 대출의 월 원리금과 다른 고금리 부채 여부
- 입주대출 희망 만기와 상환방식

입력은 질문을 한꺼번에 늘어놓지 않고 `가구 → 소득·자산 → 청약통장 → 기존 부채` 네 묶음으로 진행한다. 결과를 먼저 볼 수 있고 개인화는 선택 사항이다.

## 5. 정책대출 매칭

### 5.1 후보 상품

현재 기준으로 다음 순서로 판정한다.

1. 청년 주택드림 디딤돌 대출
2. 신생아 특례 디딤돌 대출
3. 내집마련 디딤돌 대출
4. 보금자리론
5. 정책상품 조건이 맞지 않을 때 일반 주택담보대출 비교 준비 안내

각 상품 카드는 다음만 보여준다.

- `왜 내 후보인지` 또는 `어떤 조건이 부족한지`
- 현재 제도 기준 예상 한도
- 현재 금리표 기준 예상 금리 구간
- 선택 만기 기준 예상 월 원리금
- 중도금 대출과 잔금에 적용한 뒤 남는 자금 부족분
- 신청 시점과 준비 서류
- 공식 출처와 기준일

### 5.2 금액 보정 방식

계획용 대출 한도는 다음 값 중 가장 작은 값으로 제한한다.

- 상품별 최대한도
- 공식 가격과 상품별 LTV로 계산한 한도
- DTI 또는 해당 상품의 상환능력 기준으로 계산한 한도
- 사용자가 원하는 대출액

정책대출 예상액을 입주 자금에 적용해 다음을 계산한다.

```text
입주 시 정리할 돈
= 중도금 대출 잔액
+ 분양 잔금과 옵션 잔금
+ 예상 이자·취득세·등기비

추가로 마련할 현금
= 입주 시 정리할 돈
- 예상 입주대출 실행액
```

정책대출이 중도금 대출 전액과 잔금을 모두 덮지 못하면 `부족분`을 가장 크게 보여준다. 승인액이 아니라 현재 기준의 계획용 숫자임을 숫자 바로 옆에 표시한다.

### 5.3 현재 공식 기준의 처리

- 내집마련 디딤돌은 주택가격·면적·무주택·소득·자산·DTI·가구형태를 함께 판정한다.
- 청년 주택드림 디딤돌은 연령뿐 아니라 해당 통장으로 당첨, 가입기간, 납입실적을 모두 확인한다.
- 신생아 특례는 대출 접수일 기준 출산·입양 시점을 다시 계산한다. 현재 자녀 상태를 2029년에도 그대로 적용하지 않는다.
- 보금자리론은 디딤돌 조건이 맞지 않거나 한도가 부족할 때의 보조 후보로 둔다.
- 수도권 규제, DSR, 상품 한도와 금리는 신청 시점에 달라질 수 있으므로 `2029년 재확인` 배지를 고정한다.

## 6. 화면 구성과 카피

결과 화면은 다음 순서를 유지한다.

1. `우리 집에 필요한 전체 돈`
2. `중도금은 이렇게 나갑니다`
3. `이자를 줄일 수 있는 선택`
4. `입주 때 바꿀 대출`
5. `지금부터 준비할 일`
6. `회차별 납부 내역`

내부 금융 용어보다 사용자가 이해하는 명칭을 우선한다.

| 기존 표현 | 변경 표현 |
| --- | --- |
| 내 돈 0원 | 대출 4,866만원 · 내 돈 0원 |
| 중도금 대출 60% | 중도금 6회 전액을 대출받는 기준 |
| carried loan | 입주 때 정리할 중도금 대출 |
| 정책대출 eligibility | 지금 기준으로 맞는 대출 |
| funding gap | 대출 후에도 필요한 현금 |

가장 중요한 행동 카드의 제목은 `1·2차를 내 돈으로 내면?`으로 한다. 결과는 절감액과 현금 여유를 함께 보여주며 `무조건 유리`라는 표현은 사용하지 않는다.

## 7. 데이터와 코드 경계

정책 숫자와 출처는 계산 로직에서 분리한다.

```text
src/data/policyLoans.ts
  상품별 기준, 금리표, 우대조건, 기준일, 공식 URL

src/lib/calc/interimStrategy.ts
  회차별 대출·자납·이자 절감 시나리오

src/lib/policyLoanMatcher.ts
  개인 조건과 주택가격으로 후보·탈락 사유 판정

src/lib/calc/mortgagePlan.ts
  예상 한도, 월 상환액, 입주 시 부족분 계산

src/scripts/calculator.ts
  입력 수집과 결과 렌더링만 담당
```

`src/lib/calc/`와 정책 판정 모듈은 DOM이나 Astro를 참조하지 않는 순수 TypeScript로 유지한다. 개인 조건 타입은 필요한 필드만 가지며 localStorage 저장 기본값은 `false`다.

정책 자료에는 `asOf`, `label`, `url`, `confidence`를 필수로 둔다. 기준일이 지난 자료는 계산 결과에서 `재확인 필요`로 자동 표시한다.

## 8. 오류와 불확실성 처리

- 입력하지 않은 개인 조건은 추측하지 않고 `확인 필요`로 남긴다.
- 한 조건이라도 명백히 탈락하면 탈락 사유를 한 문장으로 설명한다.
- 은행이 정해지지 않은 집단대출 금리와 수수료는 사용자가 직접 입력하며 기본값은 `가정` 배지를 붙인다.
- 공고상 알선은 보장이 아니므로 모든 중도금 회차에 `은행 심사 후 확정`을 표시한다.
- 정책대출 결과에는 `승인 보장 아님`과 공식 신청처를 함께 제공한다.

## 9. 검증 기준

### 계산 테스트

- 중도금 회차마다 `amount = loanAmount + cashAmount`가 원 단위로 일치한다.
- 대출 60% 시 6개 회차의 대출액과 총액이 공급금액의 60%와 일치한다.
- 1차 자납 시 1차 대출원금과 해당 회차 이자만 제거된다.
- 1·2차 자납 시 3~6차의 금액과 이자는 바뀌지 않는다.
- 더 이른 동일 금액 회차의 이자 절감액이 더 크다.
- 정책대출 한도는 상품한도·LTV·상환능력·희망액 중 최솟값을 넘지 않는다.
- 정책대출 실행액을 적용한 입주 자금 부족분이 음수가 되지 않는다.
- 기준일이 2029년 신청 시점보다 오래되면 재확인 경고가 나타난다.

### 화면 검증

- 모바일 첫 화면에서 `0원`만 단독으로 보이지 않는다.
- 390px 폭에서 중도금 현황, 1·2차 비교, 정책대출 후보와 부족분을 가로 스크롤 없이 읽을 수 있다.
- 키보드만으로 개인화 질문과 시나리오 버튼을 조작할 수 있다.
- 개인 조건을 저장하지 않아도 새로고침 전까지 계산이 유지된다.
- 저장을 선택하면 저장 항목과 삭제 방법을 바로 보여준다.
