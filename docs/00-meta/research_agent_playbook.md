# 검단레이크파크 리서치 에이전트 플레이북

새 에이전트가 기존 자료를 망가뜨리지 않고 같은 품질로 조사하기 위한 실행 규칙입니다.

## 1. 시작 순서

1. `README.md`와 `docs/INDEX.md`를 읽습니다.
2. `knowledge_base_rules.md`, `source_registry.md`, `update_log.md`를 읽습니다.
3. 맡은 주제와 같은 문서가 이미 있는지 `rg`로 검색합니다.
4. 기존 문서의 `updated`, `status`, `sources`를 확인합니다.
5. 현재 공식자료를 찾아 기존 사실과 비교합니다.

## 2. 조사 트랙

| 트랙 | 범위 | 주 결과물 |
|---|---|---|
| 단지 | 배치, 동, 타입, 커뮤니티, 설비, 주차 | 기준정보·동별 영향표 |
| 공사 | 골조, 외벽, 조경, 도로, 설계변경 | 월간 공정기록 |
| 생활권 | 교통, 공원, 학교, 상업, 의료, 행정 | 인프라 상태판 |
| 입주 | 옵션, 실측, 하자, 이사, 관리규약 | 체크리스트·비교표 |
| 생활 | 상가, 병원, 교육, 행사, 교통통제 | 주간 단신·생활 데이터 |

한 에이전트는 한 번에 한 트랙을 맡습니다. 여러 에이전트가 같은 Markdown 파일을 동시에 수정하지 않습니다.

## 3. 출처 우선순위

1. 모집공고·고시·공고·사업계획승인·준공공고
2. 국토교통부·인천시·검단구·인천교육청·iH 공식 자료
3. 시공사·공식 분양 홈페이지
4. 공공데이터·기관 운영정보
5. 언론·업체·지역 커뮤니티

5순위 자료는 제보와 검색 단서입니다. 핵심 일정이나 수치를 5순위 자료만으로 확정하지 않습니다.

## 4. 팩트 카드

새 사실마다 아래 항목을 먼저 채운 뒤 글을 씁니다.

| 필드 | 작성 내용 |
|---|---|
| 주장 | 한 문장으로 검증 가능한 내용 |
| 상태 | 확정/운영/공사/추진/계획/홍보/확인 필요 |
| 기준일 | 원문이 발표되거나 시행된 날짜 |
| 확인일 | 에이전트가 원문을 다시 본 날짜 |
| 1차 출처 | 주장 바로 옆에 연결할 URL·PDF·페이지 |
| 이전 상태 | 기존 문서에 적혀 있던 내용 |
| 변화 | 신규/변경/지연/철회/변화 없음 |
| 주민 영향 | 돈·시간·동선·소음·안전·교육·편의 중 무엇인가 |
| 다음 확인 | 어떤 공고나 사건이 생기면 갱신할지 |

## 5. 상태 판정 규칙

- `확정`: 모집공고, 고시, 계약서, 승인 문서로 현재 효력이 확인됨
- `운영`: 실제 이용·영업·행정서비스가 시작됨
- `공사`: 착공이 공식 확인됐으며 공정이 진행 중
- `추진`: 예타·공모·협약·설계·발주 등 행정절차 진행 중
- `계획`: 계획에 반영됐지만 착공·운영이 보장되지 않음
- `홍보`: 분양·사업 홍보물에 소개됐으나 이행 단계가 불명확
- `확인 필요`: 공식자료끼리 다르거나 최신 상태를 확인하지 못함

## 6. 글로 바꾸는 공식

한 팩트를 다음 순서로 씁니다.

1. 무엇이 달라졌는가
2. 이전 상태와 비교하면 어떤 단계인가
3. 검단레이크파크 거주자에게 무엇이 달라지는가
4. 아직 모르는 것은 무엇인가
5. 다음 업데이트는 언제·어떤 자료가 나올 때인가

`호재`, `확정`, `역세권`, `초품아`, `수변조망` 같은 표현은 행정 단계와 실제 동선을 확인하지 않고 사용하지 않습니다.

## 7. 반복 발행 판단

아래 다섯 항목 중 세 개 이상이면 블로그 후보로 등록합니다.

- 단지 거주와 직접 연결됨
- 공식 원문 해설이 필요함
- 시간이 지나면 상태가 달라짐
- 사진·수치·지도로 누적 가능함
- 독자가 행동이나 일정을 바꿀 수 있음

새 사실이 없으면 `변화 없음`을 독립 글로 양산하지 않고 기존 상태판의 확인일만 갱신합니다.

## 8. 파일 수정 규칙

- 기존 주제는 기존 문서를 갱신합니다.
- 새 문서를 만들면 `docs/INDEX.md`에 추가합니다.
- 새 출처는 `source_registry.md`, 사실 변화는 `update_log.md`에 기록합니다.
- 원문 PDF는 `sources/official`에 저장하고 `sources/README.md`에 해시를 남깁니다.
- 내부 링크 검사와 개인정보 검색을 완료한 뒤 작업을 종료합니다.

## 8-1. 자동 수집 루프 규칙

- 반복 수집은 먼저 `research_inbox/YYYY-MM-DD.md`에만 기록합니다.
- 자동 실행은 `docs/`의 확정 사실이나 블로그 초안을 수정하지 않습니다.
- 항목마다 원문 URL, 발표일, 확인시각, 상태, 이전 대비 변화를 남깁니다.
- 저녁 검토 뒤에만 후보를 `docs/`와 블로그용 문서로 승격합니다.

